# 管理員流程

平台總管理員身分由後端環境變數 `ADMIN_EMAILS` 決定，不透過前端按鈕產生，確保最高權限邊界穩固。更新環境變數後，管理員需重新登入以取得最新權限。

## 1. 每日維運核心

1. **通知清單**：檢查自己被明確指派分類的待處理案件與留言通知。
2. **待審核與待處理案件**：在看板中快速篩選「待審核」與「未回覆」案件。
3. **管理主控台 (Admin Console)**：檢視全站即時活躍趨勢、審計日誌、背景佇列與資料庫連線狀態。

## 2. 審核與案件處理

1. **審核提案**：
   - 開啟待審核提案，確認標題、內文、個資與圖片是否適合公開。
   - 點擊「審核提案」：核准後案件正式向校內公開並啟動附議倒數；若未通過，必須填寫具體說明，案件轉為「審核未過」（僅作者與管理端可見）。
2. **更新處理進度**：
   - 將「未回覆」案件更新為「處理中」，並留下清晰進度說明。
   - 結案時選擇「已完成」並填寫處理成果；若評估不可行則選擇「無法實行」並詳述限制原因。

## 3. 管理主控台（Admin Console）功能詳解

點擊側欄「管理」進入整合式管理主控台：

### 概覽與活動指標 (Overview)
- 即時呈現全站提案、設備回報、公告、留言累積數量與今日活躍度。
- 監控已結案、處理中與待審核比例，掌握校園議題推進效率。

### 使用者管理與互動限制 (User Restrictions)
- **使用者檢索**：可透過姓名、校內 Email 或 UID 全文搜尋已登入成員。
- **互動限制 (Interaction Restrictions)**：針對惡意灌水、違規發言或濫用系統之使用者，管理員可施加分級限制：
  - **限制發布提案**（Mute Proposal Creation）
  - **限制發表留言**（Mute Commenting）
  - **限制附議與按讚**（Mute Reactions & Votes）
  - **全面凍結帳號互動**（Full Suspension）
- 施加或解除限制均需填寫原因，操作即時生效並強制寫入審計日誌。

### 審計日誌 (Audit Log)
- 記錄全站所有具管理權限的操作軌跡：包含提案審核、狀態變更、公告發布與刪除、分類負責人變更、使用者互動限制施加與解除、平台設定修改。
- 提供完整時間戳記、操作者 UID、目標資源與動作細節，保障校園管理透明與可追溯性。

## 4. 分類流程與範圍授權

- **動態分類管理**：在「系統設定 → 分類與處理流程」中維護提案與設備分類，設定預設分類、附議門檻與回應期限。
- **人員與管理權限**：按分類指派專責負責人（支援多人指派）。新案件只通知指派負責人，平台總管理員不自動收到廣播。

## 5. 平台設定（媒體與資料生命週期）

在「系統設定 → 平台設定」中：
- **上傳限制**：自訂提案、設備（預設 2 張）、公告（預設 10 張）的圖片上限與單檔大小（預設 5 MB）。
- **資料保留期限**：設定已結案案件（預設 180 天）與審計日誌（預設 365 天）的自動清理排程。

## 6. 公告發布與刪除

- 在公告列表點擊「新增公告」發布重要廣播，可選填圖片。
- 支援全站公告留言總開關與單筆留言鎖定。
- 刪除公告為警示操作，確認後同步排入 Cloudinary 資源清理佇列。

## 7. 系統診斷與交接

- 定期確認 Cloudflare Queue (`novae-jobs`) 是否有堆積異常。
- 團隊交接時更新 GitHub `production` secrets 中的 `ADMIN_EMAILS` 與各服務 Token。
- 維持至少兩位受信任的管理員，避免單點管理中斷。

更深入的維護與災難復原請參考[上線後維運](operations.md)。
