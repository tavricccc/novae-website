# 使用者流程

Novae 提供一致且流暢的跨裝置體驗。桌面版使用側邊欄導覽與雙欄佈局；手機版使用符合人體工學的底部浮動導覽，並對齊安全區域（Safe Area）。

## 1. 登入與人機驗證

1. 開啟校內 Novae 網址。
2. 點擊 **透過 Google 登入**，系統呼叫 Google Identity Services 選擇校內 Google 帳號。
3. 首次登入或建立新設定檔時，系統會在背景執行隱形 **Cloudflare Turnstile** 人機驗證防護。
4. 驗證完成後自動載入使用者角色與動態分類目錄，進入看板首頁。

不符合允許網域的帳號將被後端拒絕登入。

## 2. 瀏覽與搜尋提案

1. 透過頂部或側邊分類切換不同提案分類，或進入「我的提案」。
2. 使用 `LiquidTabs` 流暢切換「進行中」與「已結案」狀態，亦可透過關鍵字即時搜尋。
3. 點擊卡片進入詳情頁；桌面版以緊湊雙欄呈現，手機版以單一自然捲動流展示正文、時間軸與討論區。
4. 私密權益案件與待審核提案受權限保護，僅作者與該分類負責人可見。

## 3. 建立提案

1. 進入提案看板，點擊「新增提案」。
2. 選擇分類、填寫標題（上限 30 字）與內文（支援 Markdown 格式，上限 1000 字）。
3. 可選填附加圖片；客戶端會以 WebAssembly (`@jsquash/webp`) 自動將圖片壓縮為 WebP 格式再進行簽名上傳。
4. 點擊「發布」，按鈕顯示旋轉進度指示並平滑過渡至完成提示。

## 4. 附議、手勢反應與留言

- **提案附議**：在開啟附議的分類中，點擊附議按鈕累積支持，按鈕具備即時樂觀更新（Optimistic Update）與失敗回滾防護。達到門檻後案件自動進入處理流程。
- **設備「我也遇到」**：在設備報修詳情中，點擊「我也遇到」記錄相同問題的反饋人數。
- **公告按讚**：點擊愛心圖示對公告表達支持。
- **討論區留言**：
  - 輸入框固定於底部導覽上方，垂直對齊頭像與送出按鈕。
  - 支援點擊留言進行「回覆」，顯示被回覆者名稱與前段引文預覽。
  - 留言不開放時顯示「留言目前不開放」提示並停用輸入。

## 5. 看懂狀態時間軸

| 狀態 | 意義 |
| --- | --- |
| 待審核 | 管理員尚未決定是否公開 |
| 審核未過 | 管理員拒絕公開；作者可查看未通過原因 |
| 未回覆 | 已達附議門檻或直接受理，等待管理單位初次回覆 |
| 處理中 | 管理單位已開始進行處理，顯示預計處理進度 |
| 未通過 | 附議期限已屆滿但未達門檻 |
| 已完成 | 案件處理完畢並提供具體結果說明 |
| 無法實行 | 經評估無法執行並說明限制原因 |

## 6. 外觀主題與個人設定

在「設定」頁面中，使用者可以：
- **自訂強調色 (Accent Themes)**：自由切換不同的主題色彩（Slate、Indigo、Emerald、Rose 等），搭配淺色／深色模式呈現個性化視覺。
- **介面語言切換**：隨時切換繁體中文與 English。
- **PWA 安裝指引**：在支援的瀏覽器中點擊安裝到手機主畫面或桌面應用程式。
- **推播通知開關**：開啟或關閉 Web Push 推播通知，系統具備 7 天心跳節流機制避免重複註冊。

## 7. 通知機制

| 事件 | 站內與推播通知對象 |
| --- | --- |
| 新公告發布 | 所有已登入之校內成員 |
| 提案／公告留言 | 被回覆之留言作者，或內容作者（排除操作者本人） |
| 提案狀態變更 | 提案作者與所有附議者 |
| 附議達標 | 提案作者與所有附議者 |
| 設備狀態變更 | 報修作者與所有標記「我也遇到」之使用者 |
| 新提案建立 | 該提案分類明確指派之負責人（排除作者） |
| 新報修建立 | 該設備分類開啟通知之負責人（排除作者） |

若使用過程遇到權限或功能異常，請向管理員反映並參考[一步一步排錯](troubleshooting.md)。
